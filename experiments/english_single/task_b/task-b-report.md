## 问题和研究动机

问题是：模型在训练中使用的上下文长度发生变化时，模型对短历史和长历史的预测能力如何沿训练步骤变化？具体比较在训练中点保持 128、保持 512、从 128 切换到 512、从 512 切换到 128 四种路径。

这属于 training dynamics，因为变量作用在参数更新过程：窗口长度改变了每个目标 token 能看到的历史范围、RoPE 位置范围和窗口边界重置方式。它不是只在训练结束后改变生成 prompt 的长度。

英文单语方案是在旧中英方案之后重新建立的。TinyStories 的文体和词汇分布更单一，使上下文长度成为更容易解释的主要变量。

## 假设

- `parent128` 的长上下文收益会较小或为负；`parent512` 会形成正的长上下文收益。
- `128-512` 切换后，`L512` 应快速下降，`G=L128-L512` 应从负值变为正值。
- `512-128` 切换后，`L128` 可能继续下降，但 `G` 应低于 `512-512`，表示长上下文能力会减弱。

这些判断来自因果注意力的可见范围：128 token 训练不能让目标依赖更远的 token；512 token 训练允许这种依赖，但并不保证模型一定学会使用它。最后一句是保留的不确定性。

## 实验设计

模型结构固定为 8 层 decoder-only Transformer、hidden size 512、8 heads、最大 context 512、16k 英文 SentencePiece tokenizer，约 33.4M 参数。两条父路径从同一个 `initial.pt` 随机状态开始：

```text
initial
├─ parent128 ──┬─ 128-128
│              └─ 128-512
└─ parent512 ──┬─ 512-512
               └─ 512-128
```

每阶段 9766 个 optimizer steps，每步 8192 个目标 token；阶段预算为 80,003,072 token，整条路径为 160,006,144 token。父阶段训练到相同 token 中点后复制完整状态，子路径只改变第二阶段 context。四条路径的学习率日程、optimizer、数据 RNG、验证窗口和评估目标保持一致。

## 测量和数据完整性

验证使用固定的 64 个英文窗口。`L128`、`L256`、`L512` 都只计算窗口最后 128 个相同目标位置，避免不同历史长度比较了不同目标。`G=L128-L512` 越大，代表 512 历史相对 128 历史的 loss 收益越大。

`experiments/english_single/task_b/completion.json` 报告 `data_chains_match: true`。四条路径的 `data_chain` 都是：

`715c475a89d097373994272c78a25311b7d41ec05958a80facf17ffb37efcd24`

新数据身份固定在 `experiments/english_single/task_b/manifest.json`，其中记录了英文 train/val token 文件和 tokenizer 的 SHA-256。旧中英数据、旧 tokenizer、旧 checkpoint 和旧日志不在新配置的输入路径中。

## 结果

### 父阶段分叉点

| 状态 | 训练 context | L128 | L512 | G |
|---|---:|---:|---:|---:|
| parent128 | 128 | 1.8930 | 3.3590 | -1.4660 |
| parent512 | 512 | 1.9173 | 1.7273 | 0.1900 |

父阶段已经产生了明显不同的 context profile：128 训练的模型在 512 历史评估下反而更差，512 训练的模型已经获得约 0.19 的长历史收益。这使第二阶段的切换有可解释的起点。

### 第二阶段起点、中点和终点

| 路径 | 第二阶段开始 L128/L512/G | 中点 L128/L512/G | 最终 L128/L512/G |
|---|---|---|---|
| 128-128 | 1.8935 / 3.3563 / -1.4628 | 2.0762 / 2.9718 / -0.8956 | **1.7874 / 3.6949 / -1.9074** |
| 128-512 | 1.8954 / 3.0221 / -1.1267 | 2.0762 / 1.6452 / 0.1794 | **1.7919 / 1.6099 / 0.1819** |
| 512-512 | 1.9163 / 1.7261 / 0.1902 | 2.0778 / 1.9102 / 0.1676 | **1.7931 / 1.5944 / 0.1986** |
| 512-128 | 1.9161 / 1.7262 / 0.1899 | 2.0778 / 1.9102 / 0.1676 | **1.7852 / 1.6315 / 0.1537** |

### 结果解释

`128-512` 支持第二个假设：切换到 512 后，`L512` 从 3.0221 降到 1.6099，`G` 从 -1.1267 变成 0.1819；`128-128` 的 `L512` 最终升到 3.6949，`G` 变成 -1.9074。两条路径的 `L128` 最终接近，说明差异主要集中在长历史利用，而不是所有能力都变好或变坏。

`512-128` 支持第三个假设的相对部分：`L128` 最终为 1.7852，略低于 `512-512` 的 1.7931；但 `L512` 为 1.6315，高于 `512-512` 的 1.5944，`G` 也从 0.1986 降到 0.1537。因此短窗口训练仍能改善短历史预测，但长历史收益减弱。这里不能把它称为完全遗忘，因为绝对 `L512` 仍比父阶段 1.7262 更低。

`128-128` 的 `L128` 最终最低并不表示它整体最好：它的 `L512` 很差。这个结果说明只看单一 context loss 会掩盖训练目标的 trade-off，必须同时报告多个历史长度。

固定 prompt 的生成样例已写入四个 `samples.json`。样例能帮助检查文本是否仍有故事结构，但没有建立自动质量分数，所以本报告不把主观生成质量作为主要证据。

## 失败、debug 和设计冲突

本次英文方案遇到并记录了两个真实启动问题：

1. 基础训练从第 6000 步恢复时，checkpoint 用 `map_location=cuda` 把 CUDA RNG ByteTensor 映射到了 GPU；`torch.cuda.set_rng_state_all` 要求 CPU ByteTensor，因此恢复在第一批数据前失败。定位到 RNG 恢复调用后，修复为恢复前 `.cpu()`，随后训练完成。
2. Task B 首次启动的 prompt selector 仍要求中文 Unicode 字符，英文验证集因此报 `Not enough long Chinese documents`。检查验证文件和选择器后，改为中文存在时选中文、否则选足够长的英文文档；失败启动没有创建 checkpoint。

训练日志中的 `skipped_updates` 是训练器针对非有限数值的既有保护计数；四条路径最终都记录为 4，未导致路径中断。没有发现数据链不一致、checkpoint 缺失或验证窗口变化。

## 结论

在这个英文 TinyStories、33.4M 参数模型和约 160M token 的单次实验中，训练 context 的变化主要改变了模型能否利用长历史：

- 128→512 能在后半程快速建立长历史能力；
- 512→128 仍能提高短历史能力，但长历史收益下降；
- 保持 128 与保持 512 的终点 profile 差异很大；
- 结论由固定目标的多 context loss 支持，生成样例只作辅助。

因此，假设 H2 得到支持，H3 得到部分支持，结果没有绕过与预期不一致的短历史/长历史 trade-off。

## 仍然不知道的事情

- 只有一个随机种子、一个 TinyStories 训练/验证划分和一个模型规模，不能判断结论是否普遍成立。
- 还不知道切换点放在四分之一、四分之三或多次切换时，转移速度和最终 profile 是否相同。
- 还不知道更长训练是否会让 `128-512` 与 `512-512` 收敛到相同水平，或让 `512-128` 的差距继续扩大。
- `G` 同时包含可见历史变化和 RoPE 位置编号、窗口边界效应，不能把它解释为纯粹的语义远距离依赖。
- 生成文本没有自动的连贯性评估，不能仅凭样例排序四条路径。
